## Changed

- `on_video_ended` / `on_audio_ended`, `VideoProcessorBase.on_ended()` / `AudioProcessorBase.on_ended()`, and the `on_ended` of the source and sink track factories now run on a thread of their own with the session's script run context attached. A callback that blocks no longer stalls every session of the app, and `st.session_state` in it now reaches the session that started the stream, even after the page has closed, where it used to hit a process-wide stand-in. The callback no longer runs on the server's event loop, so it cannot use that loop's `asyncio` APIs, and it can finish after `webrtc_streamer()` has returned from the run that STOP triggers. Other `st.*` calls in it have no effect. A source track's callback still runs inline when STOP stops the track from the session's script run. The video and audio callbacks of one stream can now run concurrently, and a callback still running when the server shuts down may not finish.
